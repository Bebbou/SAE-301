Artemis, les règles du jeu

La référence commune de l'équipe : ce qu'on fait, comment on nomme les choses, et ce qu'il faut vérifier avant chaque rendu. En cas de doute, on suit cette page ; si elle a tort, on la corrige (et on prévient les autres).

Moteur Phaser 3.80 Résolution 1280 × 720 Modes Solo & Duo Cible Borne d'arcade

01Le jeu en bref

Résumé du brainstorm, pour que tout le monde code vers le même jeu.

Concept

Rogue-like vu de dessus sur la Lune. Les joueurs sautent d'une fusée dans un ravin et descendent niveau après niveau.

Mécanique signature

La lumière : certains ennemis sont mignons dans le noir et effrayants dans la lumière, d'autres ne sont visibles que dans le noir. La torche s'allume et s'éteint.

Progression

Une échelle apparaît pour descendre. Sa probabilité augmente quand les ennemis sont vaincus et qu'on casse des cailloux. Classement au nombre de niveaux atteints.

Zone de repos

Statue d'un dieu grec : on offre des pierres lunaires en échange de vie ou de stamina.

Équipement

  • Pioche (frappe, casse les cailloux)
  • Fusil laser (tir auto, auto-visée)
  • Switch entre les deux

Boosts

  • Soin · Stamina · Munitions
  • Meilleure torche · Bombe
  • Vitesse temporaire

HUD

  • Vie (rose/orange) · Stamina
  • Pierres lunaires · Munitions
  • Outil équipé · Chrono
Point de design ouvert L'échelle s'active « quand les deux joueurs sont dessus », mais le jeu doit aussi marcher en solo. Il faut décider de la règle solo (un seul joueur suffit ?).

04Règles imposées

Non négociables : elles viennent des consignes et sont vérifiées au rendu.

Noms de fichiers et de dossiers Uniquement minuscules, chiffres, _ et -. Pas de majuscules, pas d'accents, pas d'espaces.
ExempleOK ?Pourquoi
run_down.png✓—

Chemins

Toujours relatifs, jamais absolus :

// OK

// PAS OK
this.load.image("img_ciel", "/src/assets/sky.png");

07Conventions de code

La propreté et la compréhension du code sont notées.

Une scène par fichier

Chaque scène dans js/, déclarée dans la liste scene de index.js. key identique au nom de la classe.

Pas de copier-coller

Si du code sert dans 2 scènes ou plus (créer le joueur, le HUD, un ennemi…), il va dans fonctions.js ou dans son propre fichier.

Pas de nombres magiques

Vitesses, dégâts, durées, probabilités : en constantes nommées en haut du fichier. Ça rend l'équilibrage beaucoup plus simple.

Commentaires en français

On explique le pourquoi, pas le quoi. Chaque fonction a une ligne qui dit ce qu'elle fait.

let / const

Plutôt que var. Indentation de 2 espaces, points-virgules en fin de ligne.

Debug

debug: true dans index.js pendant le dev, à passer à false avant chaque rendu.

// Exemple de constantes en haut d'un fichier
const VITESSE_JOUEUR = 160;     // px/s
const VITESSE_SPRINT = 260;     // px/s, consomme de la stamina
const DUREE_BOOST_VITESSE = 5000; // ms

08Commandes (borne d'arcade)

Un joystick + 6 boutons par joueur, sur deux rangées de trois. Les deux joueurs ont les mêmes actions, dans le même ordre : seules les touches clavier changent. Elles sont définies dans TOUCHES_J1 et TOUCHES_J2 (js/fonctions.js).

Joueur 1 · joystick = flèches

Flèches
IInteragir en face
OInteragir avec un objet
PAllumer / éteindre la lampe
KFrapper / tirer
LSprint
MChanger d'équipement

Joueur 2 · joystick = ZQSD

ZQSD
RInteragir en face
TInteragir avec un objet
YAllumer / éteindre la lampe
FFrapper / tirer
GSprint
HChanger d'équipement
Interactions « Interagir en face » (I pour le joueur 1, R pour le joueur 2) sert à remonter par l'échelle. « Interagir avec un objet » (O / T) sert à faire une offrande à la statue de la salle safe : chaque pierre lunaire rend 5 PV (jusqu'à 5 pierres par appui) et la stamina revient d'un coup. À tester sur la borne le 2 octobre.

Rappel des consignes : une borne, ce n'est pas un PC. Pas de souris, pas de texte à taper. Le joueur ne connaît pas le jeu : il faut un écran de commandes et une prise en main guidée.

10Workflow Git

Le but : ne jamais casser le jeu des autres.

1 · Avant de coder

git pull, toujours.

2 · Pendant

Une branche par fonctionnalité : feature/torche, fix/collision-murs.

3 · Commits

Petits et fréquents, message clair : ajout du sprint et de la stamina.

4 · Avant de fusionner

On lance le jeu : si ça plante, ça ne va pas sur main.

git pull
git checkout -b feature/torche
# … on code, on teste …
git add .
git commit -m "ajout de la torche (allumer / éteindre)"
git push -u origin feature/torche
# puis Pull Request sur GitHub vers main
Les maps Tiled Les fichiers .tmx / .tmj fusionnent très mal. Une seule personne modifie une map à la fois : on prévient le groupe.

11Utilisation de l'IA

Autorisée, mais « intelligente et raisonnée ».

  • Code : on doit comprendre et savoir expliquer tout code généré. Les profs posent des questions en semaine 2.
  • Assets (images, sons, vidéos) : libre.
  • game.json : rédigé par nous.
  • Prompts : à lister dans la note technique. On les note au fur et à mesure (date, qui, outil, prompt, à quoi ça a servi) pour ne pas avoir à les retrouver à la fin.
