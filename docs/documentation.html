Artemis, les règles du jeu

La référence commune de l'équipe : ce qu'on fait, comment on nomme les choses, et ce qu'il faut vérifier avant chaque rendu. En cas de doute, on suit cette page ; si elle a tort, on la corrige et on prévient les autres.

le jeu en bref

Résumé du brainstorm, pour que tout le monde code vers le même jeu.

Concept

Rogue-like vu de dessus sur la Lune. Les joueurs descendent de niveau en niveau, dans le noir, à la recherche de pierres lunaires.

Mécanique signature

La lumière : le jeu est dans le noir, la torche éclaire un cône que les murs arrêtent, et les ennemis ne se voient que dans la lumière.

Progression

Un trou caché sous l'un des cailloux mène au niveau suivant. Le classement se fait au nombre de niveaux atteints.

Zone de repos

Une salle safe rare, avec la statue d'un dieu grec : on y offre des pierres lunaires contre des PV et de la stamina.

Équipement

  • Pioche (casse cailloux et cristaux)
  • Fusil laser
  • Changement avec un bouton

Bonus

  • Potion de soin
  • Torche plus longue
  • Vitesse temporaire

Ennemis

  • Slime (niveau 1)
  • Alien vert, tire (niveau 2)
  • Alien rouge, rapide (niveau 3)

HUD

  • Vie et stamina
  • Pierres lunaires
  • Outil équipé et bonus actifs
Règle de l'échelle, en solo et en duo Tous les joueurs de la partie doivent être sur le trou pour descendre (un joueur seul suffit donc en solo). Pour remonter, ils doivent tous être près de l'échelle et l'un d'eux appuie sur « interagir en face ».

Non négociables : elles viennent des consignes et sont vérifiées au rendu.

Toujours relatifs, jamais absolus :

// ok

// pas ok

Autres contraintes

  • Le jeu part du template Moodle : on garde son organisation (index.js à la racine = point de départ).
  • game.json au format imposé, rempli par nous (pas par une IA), avec des apostrophes droites ', pas courbes.
  • Un game.json doit être du JSON valide, sans retour à la ligne dans une chaîne (on écrit \n) : sinon la borne ignore le jeu en silence.
  • Résolution 1280 × 720 (16/9).
  • Assets libres de droits uniquement, avec les auteurs crédités. Un seul asset non libre peut coûter cher.

conventions de code

La propreté et la compréhension du code sont notées.

Un fichier, un rôle

La lumière, les ennemis, les drops ont chacun leur fichier dans js/. Les scènes sont déclarées dans index.js, avec une key égale au nom de la classe.

Pas de copier-coller

Si du code sert à plusieurs endroits (créer un joueur, un halo, un texte flottant), il va dans un fichier commun.

Pas de nombres magiques

Vitesses, dégâts, durées, probabilités : en constantes nommées en haut du fichier. L'équilibrage devient simple.

Commentaires en français

On explique le pourquoi, pas le quoi. Chaque fonction a une ligne qui dit ce qu'elle fait.

let / const

Plutôt que var. Indentation de 2 espaces, points-virgules en fin de ligne.

Debug

debug: true dans index.js pendant le dev, à passer à false avant chaque rendu.

// exemple de constantes en haut d'un fichier
const VITESSE_JOUEUR = 160;  // px/s
const VITESSE_SPRINT = 260;  // px/s, consomme de la stamina
const PV_PAR_PIERRE = 5;     // PV rendus par une pierre offerte à la statue

commandes de la borne

Un joystick et 6 boutons par joueur, sur deux rangées de trois. Les deux joueurs ont les mêmes actions, dans le même ordre : seules les touches clavier changent. Elles sont définies dans TOUCHES_J1 et TOUCHES_J2 (js/fonctions.js).

Interactions « Interagir en face » (I / R) sert à remonter par l'échelle. « Interagir avec un objet » (O / T) sert à faire une offrande à la statue de la salle safe : chaque pierre lunaire rend 5 PV (jusqu'à 5 pierres par appui) et la stamina revient d'un coup.

Rappel des consignes : une borne, ce n'est pas un PC. Pas de souris, pas de texte à taper. Le joueur ne connaît pas le jeu : il faut un écran de commandes (il existe dans le menu) et une prise en main guidée.

En Phaser, une couleur s'écrit 0x9DD9FF (tint, graphics) ou "#9DD9FF" (texte).

workflow git

Le but : ne jamais casser le jeu des autres.

1 · Avant de coder

git pull, toujours.

2 · Pendant

Une branche par fonctionnalité : feature/torche, fix/collision-murs.

3 · Commits

Petits et fréquents, message clair : ajout du sprint et de la stamina.

4 · Avant de fusionner

On lance le jeu : si ça plante, ça ne va pas sur main.

git pull
git checkout -b feature/torche
# on code, on teste
git add .
git commit -m "ajout de la torche (allumer / éteindre)"
git push -u origin feature/torche
# puis Pull Request sur GitHub vers main
Les maps Tiled Les fichiers .tmx / .tmj fusionnent très mal. Une seule personne modifie une map à la fois : on prévient le groupe.

utilisation de l'ia

Autorisée, mais « intelligente et raisonnée ».

  • Code : on doit comprendre et savoir expliquer tout code généré. Les profs posent des questions en semaine 2.
  • Assets (images, sons, vidéos) : libre.
  • game.json : rédigé par nous.
  • Prompts : à lister dans la note technique. On les note au fur et à mesure (date, qui, outil, prompt, à quoi ça a servi) pour ne pas avoir à les retrouver à la fin.
